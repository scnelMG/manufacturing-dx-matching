# 한계와 회고

## 정답 데이터 부재

이 프로젝트의 가장 큰 한계는 매칭의 정답이 없었다는 점입니다. 어떤 공급기업이 특정 수요기업에 가장 적합한지 판단할 라벨 데이터가 없었기 때문에, 추천 결과를 객관적인 정량 지표로 검증하기 어려웠습니다.

## 가중치 검증 한계

최종 점수는 기술 적합도 80%, 기업 신뢰도 20%로 구성했습니다. 이 비율은 문제 정의와 도메인 논리에 기반해 설정했지만, 실제 최적 비율인지 검증할 수 있는 기준 데이터는 없었습니다.

## 데이터 품질 의존성

기업 소개와 기술 설명의 품질이 임베딩 결과에 직접적인 영향을 줬습니다. 홈페이지 크롤링과 LLM 요약으로 부족한 정보를 보완했지만, 기업별 홈페이지 구조와 설명 밀도 차이를 완전히 통제하기는 어려웠습니다.

## 개선 방향

- 전문가 검토 기반의 소규모 정답셋 구축
- 추천 결과에 대한 Top-K 적합도 평가
- 가중치 민감도 분석
- 기업 규모, 업종, 지역 등 추가 제약 조건을 반영한 재랭킹
- 매칭 결과에 대한 사용자 피드백 루프 설계

## 배운 점

정답이 없는 문제일수록 모델 설계보다 평가 체계 설계가 더 중요할 수 있습니다. 이번 프로젝트를 통해 좋은 알고리즘을 만드는 것뿐 아니라, 좋은 결과를 어떻게 정의하고 검증할지 먼저 설계해야 한다는 점을 배웠습니다.
